# 2D Segmentation and Existence Classification

BiomedParse v2 supports 2D segmentation with built-in existence classification.
Each training annotation pairs a binary mask with candidate text prompts. The
model predicts a segmentation mask and an existence logit for each prompt;
automatically generated negative examples teach it when a requested target is absent.

**Our dedicated pretrained 2D model will be released in the future.** Until then,
train on your data or fine-tune a compatible v2 checkpoint. The released 3D weights
can initialize the architecture but do not establish accuracy in new 2D domains.
The v1 checkpoint is not directly compatible with the v2 existence classifier.

## Data Format

Prepare disjoint training and validation splits (split by patient/subject where
applicable). Use 8-bit grayscale/RGB images and one binary mask per annotation:
zero is background and any nonzero value is foreground, so 0/255 masks work
directly. Multiple annotations may reference the same image. Every annotation's
`sentences` must describe the same mask, not different targets within an image.
Image and mask dimensions must match; the loader pads and resizes them to 512 by
512, using nearest-neighbor interpolation for masks. RGB channels are preserved.

```text
YOUR_DATASET/
  train.json
  train/
    image001_CT_abdomen.png
  train_mask/
    image001_CT_abdomen_liver.png
  test.json
  test/
    image002_CT_abdomen.png
  test_mask/
    image002_CT_abdomen_liver.png
```

Each manifest has the following structure (use validation filenames in `test.json`):

```json
{
  "images": [{"id": 0, "file_name": "image001_CT_abdomen.png"}],
  "annotations": [
    {
      "image_id": 0,
      "mask_file": "image001_CT_abdomen_liver.png",
      "sentences": [
        {"raw": "liver in abdomen CT"},
        {"raw": "hepatic tissue in abdominal CT"}
      ]
    }
  ]
}
```

An annotation may instead supply `file_name` directly, without an `images` table.
Sentence text can use `raw` or `sent`. `category_id` is not used to identify target
classes; each annotation's sentences identify its target. The default validation
split is named `test`; override `scratch.validation_split=val` for `val.json`,
`val/`, and `val_mask/`. Do not use your final held-out test set for model selection.

## Automatic Negative Sampling

Each training sample is selected for augmentation with probability
`scratch.negative_ratio` (default 0.15). Selected samples follow this order:

1. **Class negative:** if eligible absent classes exist, select one random prompt
  uniformly from their deduplicated prompt pool. Keep the image and use an empty mask.
2. **Crop negative:** otherwise, sample a square outside the union of all annotated
  masks for the image. Crop the image and mask together, keeping the original prompts.
3. **Positive crop:** if no empty crop exists, sample a square containing foreground
  from the current target mask. Keep its prompts and cropped mask as a positive example.

Both crop types use side lengths from `max(1, floor(min_crop_ratio * min(H, W)))`
through `min(H, W)`, inclusive. The default `min_crop_ratio=0.5` gives approximately
50-100% of the shorter image dimension. Positions are sampled from valid regions
at a random size, with the minimum size as fallback. Padding is never used to
invent background. If the current mask is already empty and no empty crop is
available, the original empty-mask example is retained; foreground is never fabricated.
Nearest-neighbor mask resizing falls back to max pooling only if it would erase
all foreground, preserving the positive existence target.

Classes recorded in the split's JSON are assumed exhaustively annotated: a class
not annotated for an image is treated as absent within the same modality/site.
This uses mask names `[IMAGE]_[MODALITY]_[SITE]_[TARGET].png` (use `+` for spaces).
All annotations for the image are considered. Class identities ignore case and
repeated whitespace; classes sharing a known prompt alias with an annotated class
are excluded. Use consistent target names and candidate synonyms: the sampler
cannot infer arbitrary semantic equivalence or anatomical containment (for example,
kidney versus renal cortex). Crop validity also requires all instances of the queried
target to be annotated.

Optionally, `alt_classes.json` can contain `{"negative": ["verified absent target"]}`
for classes known absent throughout the dataset. These are available to the class
strategy without inferring absence from incomplete annotations. Entries conflicting
with known class names or candidate sentences are rejected. The dataset author
must verify absence, including synonyms not recorded in the annotations.

For partially annotated data, disable inferred class absence with
`+datamodule.datasets.train.exhaustive_annotations=false`.
Set crop size with `+datamodule.datasets.train.min_crop_ratio=0.5`, or set
`scratch.negative_ratio=0` to disable this augmentation entirely. There are no
unrelated-prompt negatives or strategy weights. The selection probability is not
a guaranteed negative fraction because some selected samples remain positive.

Negative selection is resampled each time a training annotation is loaded.
Each annotation supplies `scratch.num_prompts` masks (default 4), with candidate
sentences sampled with replacement for positives and both crop types. Class
negatives repeat their single selected prompt across these slots to keep training
batches a fixed size. The loss derives existence targets
from mask contents, trains the classifier on positives and negatives, and applies
segmentation/edge losses only to positives. Validation never synthesizes negatives
by default and uses a fixed per-annotation seed. Include genuine empty-mask examples
to evaluate absence; validation covers sampled prompts, not every candidate sentence.

## Train or Fine-Tune

Install the training dependencies from the [main README](../../README.md#installation).
Run the training entry point from the repository root:

```bash
python -m azureml.acft.image.components.olympus.app.main \
  --config-path "$PWD/configs" --config-name finetune_biomedparse_2D \
  scratch.data_root=/absolute/path/to/YOUR_DATASET \
  experiment_output_dir=/absolute/path/to/output \
  olympus_checkpoint.loader.checkpoint_path=/absolute/path/to/compatible_v2.ckpt
```

To train from scratch, replace the last override with
`olympus_checkpoint.load_checkpoint=false`. This skips weight initialization;
it is not a recommendation that a small custom dataset is sufficient to train
the full model. The CLIP tokenizer is downloaded on first use unless cached.

The training configuration uses `src/model/biomedparse.py` with the binary-mask
loader in `src/datasets/biomedparse_dataset_2D.py`. The image inference model in
`src/model/biomedparse_2D.py` loads the resulting checkpoints.

The default configuration uses one GPU, mixed bfloat16 precision, four edge queries,
and batch size 1. Adjust `datamodule.dataloaders.train.batch_size`,
`trainer.max_epochs`, and `optimizer.lr` for your data and hardware.
On hardware without bfloat16 support, select a supported `trainer.precision`.
Checkpoint loading restores the saved normalization buffers as well as weights;
do not discard them when exporting a fine-tuned model.

For multiple GPUs, add `trainer.devices=2` (or `trainer.devices=auto` for all visible
GPUs) to the same command. The training batch size is per GPU. Keep the default
DDP strategy with unused-parameter detection. See [multi-GPU usage](../../README.md#multi-gpu-usage)
for GPU selection, effective batch size, and memory requirements.

## Inference

```bash
python inference_2d.py --image /path/to/image.png \
  --prompt "liver" --prompt "right kidney" \
  --checkpoint /path/to/your_2d_checkpoint.ckpt --output outputs/masks.npz
```

The output contains per-prompt `masks`, existence-filtered `probabilities`,
`existence_probabilities`, and `prompts`. Masks retain the original image size and
may overlap. `--threshold` sets the existence cutoff (default 0.5).

For a folder of images, replace `--image` with `--input_dir` and pass an output
directory to `--output`. The same prompts apply to each image. To distribute files
across GPUs, replace `python` with `torchrun --standalone --nproc-per-node=2`.
Results are named after the complete input filename, for example `image.png.npz`.
